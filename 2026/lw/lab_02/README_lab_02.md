## 5. Минимальные теоретические сведения

**Колоночное хранение.** Parquet размещает рядом значения одной колонки, а не одной записи.
Отсюда два следствия. Первое: однородные данные сжимаются в разы лучше — работают dictionary
encoding и RLE. Второе: запрос, которому нужны две колонки из десяти, читает только эти две.
Это **column pruning**.

**Партиционирование.** `partitionBy("robot_id")` раскладывает данные по каталогам вида
`robot_id=robot-7/`. Запрос с фильтром по этой колонке пропускает лишние каталоги целиком —
**partition pruning**. Значение ключа при этом физически не хранится в файлах: оно закодировано
в имени каталога.

**Метрики работы.**

Коэффициент уменьшения объёма:

```
C = S_CSV / S_Parquet
```

Ускорение чтения:

```
Speedup = T_CSV / T_Parquet
```

Результаты зависят от runtime Colab и файлового кэша, поэтому каждое измерение повторяется
не менее трёх раз, а итогом берётся **медиана**: она устойчивее среднего к единичному выбросу
при первом «холодном» чтении.

## 6. Ход работы

### Часть 1. Три физические версии набора

1. Открыть `lab_02_student.ipynb` в Colab, выполнить установочную ячейку и создать

3. Записать набор в CSV с заголовком; убедиться, что Spark создал каталог с файлами `part-*`,

5. Записать набор с `partitionBy("robot_id")`; проверить, что создано 12 каталогов вида

8. Записать тот же набор **без колонки `payload`** (SHA-256, высокоэнтропийная строка), заново
   рассчитать коэффициент и письменно объяснить, почему он изменился именно так.
9. Записать набор четырьмя кодеками — `uncompressed`, `snappy`, `gzip`, `zstd` — измерив для

### Часть 3. Бенчмарк чтения

    из-за ленивости ничего не прочитается.
12. Выполнить одинаковый запрос `robot_id == "robot-7"` к каждой из трёх версий, минимум
    по три повтора; рассчитать ускорение относительно CSV.
13. Повторить замер CSV с **явно заданной схемой** вместо `inferSchema`. Сравнить три числа
    и письменно объяснить, почему это уточнение принципиально для корректности бенчмарка.

### Часть 4. Pruning и мелкие файлы

14. Выполнить `explain(mode="formatted")` для запроса к partitioned Parquet; найти
    `PartitionFilters`, `PushedFilters` и `ReadSchema`, письменно объяснить назначение каждого.
