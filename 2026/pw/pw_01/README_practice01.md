## 2. Теоретический минимум

### 2.1. Big Data и модель 5V

В образовательной среде данные могут поступать из LMS, электронного журнала, тестов, форумов, тренажёров и других цифровых сервисов.

| 5V | Смысл | Пример в нашей работе |
|---|---|---|
| **Volume** | объём | исходный OULAD содержит миллионы записей взаимодействий |
| **Velocity** | скорость появления | реальные LMS-события поступают постоянно; CSV — сохранённый срез |
| **Variety** | разнообразие | студент, день, ресурс, тип активности, результат |
| **Veracity** | качество и достоверность | пропуски, дубли, необычно высокая активность, ошибки журналирования |
| **Value** | педагогическая ценность | аналитика помогает сформулировать вопрос и предложить поддержку |

### 2.2. Цифровой образовательный след

В работе используются:

- **процессный след** — `day`, `id_site`, `activity_type`, `sum_click`;
- **результативный след** — `final_result`;
- обезличенный идентификатор — `id_student`.

ФИО, контакты, геолокация, изображения, биометрия и другие лишние данные в учебный файл не включаются.

### 2.3. Таблица, CSV и DataFrame

**CSV** — текстовый табличный формат.  
**DataFrame** в `pandas` — таблица в памяти Python.

Пример:

```text
id_student | day | id_site | sum_click
-----------|-----|---------|----------
12345      | 4   | 678     | 7
```

### 2.4. Агрегирование

Исходная таблица содержит подробные записи по ресурсам. Для педагогического анализа часто требуется перейти на уровень **одного обучающегося**.

Например:

```python
early.groupby("id_student")["sum_click"].sum()
```

В SQL аналогичная идея записывается так:

```sql
SELECT
  id_student,
  SUM(sum_click)
FROM `project.dataset.table`
GROUP BY id_student;
```

Соответствия:

| pandas | GoogleSQL |
|---|---|
| `df[...]` | `WHERE` |
| `groupby(...)` | `GROUP BY` |
| `sum()` | `SUM()` |
| `nunique()` | `COUNT(DISTINCT ...)` |
| `sort_values()` | `ORDER BY` |

### 2.5. Корректная интерпретация

Низкая активность в LMS **не означает**, что обучающийся «слабый», «немотивированный» или «не способен учиться».

Возможны другие причины: работа офлайн, нестабильный интернет, другой способ изучения материалов, занятость, состояние здоровья, особенности интерфейса или неполнота журналирования.

Правильная формулировка:

> «Получен статистический сигнал, который требует педагогической проверки».

# 7. Базовая аналитика: первые 30 дней

## В Colab

```python
early = df[df["day"].between(0, 29)]

student_metrics = (
    early.groupby("id_student")
    .agg(
        total_clicks=("sum_click", "sum"),
        active_days=("day", "nunique"),
        resources_used=("id_site", "nunique"),
        final_result=("final_result", "first"),
    )
    .reset_index()
)
```

Для эталонного файла в первые 30 дней присутствуют записи для:

```text
1767 обучающихся
```

## В BigQuery

```sql
SELECT
  id_student,
  SUM(sum_click) AS total_clicks,
  COUNT(DISTINCT day) AS active_days,
  COUNT(DISTINCT id_site) AS resources_used
FROM `YOUR_PROJECT_ID.learning_analytics.oulad_events`
WHERE day BETWEEN 0 AND 29
GROUP BY id_student
ORDER BY total_clicks DESC;
```

Запрос должен вернуть **1 767 строк**.

# 8. Сквозной пример: простой сигнал низкой ранней активности

Для первых 30 дней:

- 25-й перцентиль по `total_clicks` — **34**;
- 25-й перцентиль по `active_days` — **4**.

Сигнал создаётся только тогда, когда выполняются **оба** условия:

```text

И
active_days <= 4
```

В эталонном наборе:

- группа с сигналом — **387** обучающихся;
- группа без сигнала — **1 380**;
- `Pass/Distinction` в группе с сигналом — около **36,4%**;
- `Pass/Distinction` без сигнала — около **65,3%**.

Это **не доказательство причинности** и не диагноз. Показатель используется только как учебный пример прозрачной аналитической эвристики.

# 10. BigQuery Sandbox: что важно помнить

По актуальной документации Google Cloud для Sandbox:

- доступно до **10 GiB хранилища за весь срок использования Sandbox**;
- удаление данных не возвращает эту квоту;
- бесплатно доступно до **1 TiB обработанных запросами данных в месяц**;
- таблицы, представления и разделы автоматически истекают через **60 дней**;
- часть функций, включая DML и streaming, в Sandbox не поддерживается.

Официальная документация:

- Sandbox: https://cloud.google.com/bigquery/docs/sandbox
- загрузка локальных данных: https://cloud.google.com/bigquery/docs/batch-loading-data

# 12. Типичные ошибки

| Ситуация | Что проверить |
|---|---|
| Первая строка стала данными | `Advanced options → Header rows to skip = 1` |
| `Header rows to skip` показывает `0` | щёлкнуть по `0`, удалить, ввести `1`, нажать `Tab` |
| `day` или `sum_click` имеют `STRING` | пересоздать таблицу и проверить `Auto detect`; при необходимости задать схему вручную |
| SQL пишет `Not found` | проверить **Project ID**, `learning_analytics`, `oulad_events` |
